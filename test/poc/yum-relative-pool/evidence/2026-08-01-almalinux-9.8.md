# YUM relative shared-pool gate evidence — 2026-08-01

## Result

**FAIL — do not freeze the candidate managed YUM layout, SQLite physical view
path, or renderer location policy.**

Real DNF successfully consumed package metadata containing
`../../../pool/...`, but real `dnf reposync` rejected the same locations as
escaping its per-repository download directory. No absolute URL, hard-coded
domain, or absolute metadata path was used to hide the incompatibility.

## Fixture and metadata

The container built two minimal installable RPMs:

```text
sow-yum-relative-native 1.0-1 x86_64
sow-yum-relative-neutral 1.0-1 noarch
```

The x86_64 view contained native + noarch; the aarch64 view contained only
noarch. Extracting both generated primary metadata files produced exactly:

```text
x86_64:
../../../pool/s/sow-yum-relative/sow-yum-relative-native-1.0-1.x86_64.rpm
../../../pool/s/sow-yum-relative/sow-yum-relative-neutral-1.0-1.noarch.rpm

aarch64:
../../../pool/s/sow-yum-relative/sow-yum-relative-neutral-1.0-1.noarch.rpm
```

Downloaded RPM SHA-256 values matched the shared-pool source in each passing
download/install path.

## Failing reposync operation

The x86_64 command was:

```text
dnf -q reposync --repoid=sow-relative-x86 \
  --download-path=/work/reposync-x86 --arch=x86_64 --arch=noarch
```

DNF 4.14.0 returned non-zero:

```text
Error: Download target '/pool/s/sow-yum-relative/sow-yum-relative-native-1.0-1.x86_64.rpm' is outside of download path '/work/reposync-x86/sow-relative-x86'.
```

The sibling aarch64 view failed the same way:

```text
dnf -q --forcearch=aarch64 reposync --repoid=sow-relative-arm \
  --download-path=/work/reposync-arm --arch=aarch64 --arch=noarch
Error: Download target '/pool/s/sow-yum-relative/sow-yum-relative-neutral-1.0-1.noarch.rpm' is outside of download path '/work/reposync-arm/sow-relative-arm'.
reposync exit status: x86_64=1 aarch64=1
```

## Conclusion

The href is valid for ordinary DNF repository consumption but incompatible
with this real reposync client. Since reposync is an explicit P1 gate, the
candidate `dists/<dist>/<arch>` plus shared top-level `pool/` layout does not
pass. Product/architecture must choose a different layout or explicitly revise
the compatibility requirement; the fixture must not be made green with an
absolute URL or deployment-specific hostname.
