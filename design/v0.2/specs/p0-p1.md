## Intent

**Problem:** 当前 checkout 的活动入口仍是 Git/CAS/remote 驱动的 SOW V1，完全缺少 V2 P0/P1 的 Plain Create、Workspace、Repository、Dist、每仓 SQLite、恢复和封闭 CLI。

**Approach:** 建立与 V1 产品骨架隔离的 V2 活动入口，窄复用 RPM/DEB 解析与 metadata 编码原语；先测试并实现 P0，再完成相对 Pool 客户端门禁，最后测试并实现 P1。

## Boundaries & Constraints

**Always:** 以三份当前规范及既定优先级为准；先 stage/validate/fsync、pointer last；Plain 与 Managed 隔离；所有名称和破坏性路径 root-bound；生产目录只读；当前 checkout 的测试与真实客户端结果才算证据。

**Ask First:** 只有 YUM 相对 Pool 在真实 DNF/reposync 中失败并迫使改变公共 layout，或三份规范按优先级仍无法解决公共行为冲突时暂停。

**Never:** 不实现或暴露 P2/P3 命令、flag、假状态或远端配置；不导入 V1 Git/CAS/publish/sync/provider 状态模型；不修改 `/Users/vonng/pgsty/repo`；不提交、推送、签名生产仓库或发布。

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Plain | 顶层 RPM、DEB 或混合包 | flat rpm-md 与 `Packages{,.gz}`，稳定且无 SQLite | 无包/解析/冲突/renderer 失败为 1 或 6，旧索引可用 |
| Pigsty | 精确命中 32-bit 或 patroni 3.0.4 | recovery rename、无悬空引用、SHA-256 marker 最后切换 | SIGKILL 后重跑完成或回滚；矛盾证据为 5 |
| Init | 无配置或已有合法部分状态 | 创建默认对象或只补齐缺失对象 | 不覆盖/重置有效状态；配置错误为 2 |
| Repo/Dist | 固定名称与空状态 | journaled CRUD、per-repo DB、空客户端索引 | protected/非空/架构/逃逸拒绝为 6 |
| Lock | 竞争写者 | 等待、超时或 no-wait 按契约 | timeout/no-wait 为 4，互斥参数为 2 |

**Acceptance Criteria:**
- Given 当前三份规范，when 对 help、flags、输出与退出码做 preservation sweep，then P0/P1 全覆盖且 V1/P2/P3 不可见。
- Given 每个声明 crash point，when 子进程被终止并重跑，then 只有完整旧态或完整新态，无丢包、悬空索引或错误 marker。

- Given shared Pool fixture，when 两种架构运行 DNF/YUM download/install 和 reposync，then native/noarch 均通过相对 href 定位且 SHA 一致。
- Given 生产目录的前后 metadata 指纹，when 全部开发验证结束，then 指纹不变且无任何远端发布证据。
- Given 含未签名与已签名 RPM 的 Plain 目录，when 分别执行 `create --sign-with KEY` 与 `create --sign-with KEY --overwrite`，then 前者只补签未签名包、后者用 KEY 重签全部包，rpm-md 精确绑定最终字节，任一 stage/sign/commit 失败不留下未记录的原包改写。

## Design Notes

V1 仅作为 parser/renderer/safefs 的采矿区。新入口不得导入 `internal/cli`；否则同 package 的 V1 provider/remote 依赖会继续进入活动编译图。P1 SQLite 预留空的 package/membership 关系边界，但当前不注册 mutation API。
